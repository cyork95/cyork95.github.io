Faction ungating (Option A, decided 2026-11-17)

Problem

In shared zones the pack's contracts are zero-overlap: every shared/neutral quest lives only in the primary faction's guide. But that guide carried a faction header and zero per-line faction gates, so the other faction's players could not see the file at all and lost every shared quest in the zone. (A Horde player in Ashenvale saw only the 35-quest Horde file; the 55-quest main guide was hidden. An Alliance player in the Barrens had effectively no guide: the 157-quest file was Horde-gated.)

Remedy (Zephras 0.96.0 precedent)

Per-line gating complete + header dropped = the file serves both factions. The Zephras Isle twin fix proved the mechanism; this round applies it to the first four shared-zone primaries.

Gate rule (game data decides every gate)

Quest availability comes from the quest's races mask in the local data build (--product wowf + QuestieDB): 8589934770 = Horde-only, 4294967373 = Alliance-only, anything else (null included) = both.

  • Every goal line that references a quest (accept / turnin / complete / collect via drop linkage) is gated only <Faction> iff that quest's mask equals the guide's old header faction. Shared (both-mask) lines stay bare.
  • Composition appends to existing gates (only Paladin + Alliance-only quest becomes only Paladin,Alliance), exactly as the Zephras fix did (optional only Horde order for optional lines).
  • Soft-pre mini-steps (when onquest <pre> steps) are gated by the same rule using the mini-step quest's availability. The when line grammar takes only quest ids, so the gate rides a standalone step-level only <Faction> line (valid per GUIDE_FORMAT: "only limits one step or one goal"; upstream seed guides use standalone only Alliance / only Horde step lines). Only steps whose when quests are ALL old-header-faction-only are gated; mixed-availability steps (none found) would stay bare.
  • Travel lines: getfp / fly lines naming a faction-only flight point, and sethome lines for towns the other faction cannot use, take the same gate; neutral-hub lines stay bare. All four pilot guides were searched for fly, getfp, taxi, boat, zeppelin, hearth, sethome: zero travel lines of any kind, so nothing was gated and none needed to be.
  • Class/race gates already on lines stay untouched.
  • Quest lines whose quest is shared but whose objective giver/mob is faction-flavoured follow the quest's mask. The quest decides.
  • After the audit is verified, the faction header line is removed. Title, levels, zone, category and folder stay as they are.
  • Collect attribution via item drops (items.json drop linkage); manual attribution only where step context is explicit (3317 Horde via Talking Head, 211814 Alliance via Warsong Mark).
  • A quest available only to the OTHER faction inside a primary contract is an anomaly: report it, never contract or route around it silently. None found in any of the four pilot guides, and none pack-wide (see sweep).

Pack-wide sweep (standing ungating list)

Every other pack guide that carries a faction header was checked the same way: its contract quests against the data masks. Result: no guide contains a quest available only to the opposite faction (zero anomalies pack-wide; the only mixed-mask contract is zephras-isle, already per-line gated since 0.96.0). Every core/city contract below with a nonzero shared count hides shared quests from the opposite faction today and is a future ungating candidate. Companions carry no quest lines and are not part of this fix.
